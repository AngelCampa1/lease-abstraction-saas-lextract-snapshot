# US-007: Backend Gemini 3-Pass Extraction Pipeline

**Phase:** 2 — Independent Modules | **Depends on:** US-002 | **Blocks:** US-015b
**Type:** Backend
**Estimated session size:** Large

> **Renamed from "Backend Claude Extraction Service".** The pipeline migrated from Anthropic Claude to Google Gemini 3 Flash via OpenRouter, and from a single-call extraction to a 3-pass adversarial validation flow. The filename is preserved to keep tracker history consistent.

## Description

Build the AI extraction service that takes a commercial lease PDF and uses Google Gemini 3 Flash via OpenRouter to extract 126 structured fields across 16 categories. This is the core intelligence of Lextract — it turns a raw lease PDF into structured data via a 3-pass adversarial validation pipeline. There is no separate OCR step; Gemini accepts the PDF as native multimodal input.

## Required Skills

- `superpowers:test-driven-development`

## Acceptance Criteria

- [ ] System prompt includes the complete 126-field schema definition (auto-generated from `FieldRegistry`, sourced from `lextract_field_schema.json`)
- [ ] Per-pass prompts are generated by `ExtractionPromptBuilder(registry, pass_role)`:
  - Pass 1: "extract the 126 fields from this PDF"
  - Pass 2: "you are a hostile reviewer. Re-read the PDF, find errors in this Pass 1 JSON, and emit a sparse corrections patch"
  - Pass 3: "resolve this disputed value. Pass 1 said X, Pass 2 corrected to Y. Read the PDF and decide."
- [ ] Native PDF multimodal input — the PDF is base64-encoded and sent as a `file` content part to OpenRouter
- [ ] Pass 1 returns 126-field JSON with Gemini self-reported confidence (0.0-1.0) per field
- [ ] Pass 2 returns a sparse corrections patch: `{ "field_name": { "value": new_value, "confidence": 0.0-1.0, "reason": "..." } }`
- [ ] Pass 3 returns a per-field resolution: `{ "field_name": { "value": final_value, "confidence": 0.0-1.0, "winner": "pass1" | "pass2" } }`
- [ ] Critical fields (always re-checked in Pass 3 when corrected): `base_rent_annual`, `pro_rata_share`, `lease_term_months` — configurable via the registry
- [ ] Per-pass fallback model chain: each pass tries primary → fallback 1 → fallback 2 (see `docs/MODEL_CONFIGURATION.md`)
- [ ] Circuit breaker on every OpenRouter call via `pybreaker.CircuitBreaker`
- [ ] Retry on transient API errors (rate limits, 5xx) with exponential backoff
- [ ] Response validation: output matches expected schema structure; thinking-tag (`<think>...</think>`) blocks are stripped before JSON parsing
- [ ] Audit trail: each pass logs `model_slug`, `input_tokens`, `output_tokens`, `cost_usd`, `duration_ms`, and the raw response to `extraction_passes`
- [ ] Handles partial extractions gracefully (missing fields get `null` + confidence 0.0)
- [ ] All tests use mocked OpenRouter responses; no live API calls in CI

### Key Implementation Notes

- **Native PDF input:** the entire PDF is sent as a base64-encoded `file` content part. No text extraction or OCR is performed on the backend.
- **OpenRouter SDK:** uses the `openai` Python SDK with `base_url="https://openrouter.ai/api/v1"` and the OpenRouter API key.
- **Per-pass model selection:** all model slugs are read from `backend/app/core/config.py` (`PASS1_MODEL`, `PASS1_FALLBACK_MODEL`, `PASS1_FALLBACK_MODEL_2`, etc. — see `docs/MODEL_CONFIGURATION.md`).
- **Pass 2 corrections patch is sparse:** Pass 2 only emits entries for fields it wants to change. Untouched fields are kept from Pass 1.
- **Pass 3 trigger conditions:** runs only when (a) Pass 2 corrected a critical field, OR (b) a critical field has merged confidence < 0.80. Otherwise skipped to save cost.
- **Output JSON shape:** `{ "fields": { "field_name": { "value": ..., "confidence": 0.0-1.0, "source_text": "...", "pass_provenance": "pass1" | "pass2" | "pass3" } } }`
- **Thinking tags:** some Gemini Flash variants emit `<think>...</think>` blocks. The response parser strips these before JSON parsing.
- **Cost tracking:** OpenRouter response metadata includes per-call token counts and USD cost; persisted in `extraction_passes`.
- **Validator is pluggable:** custom validation logic can be passed per registry via `Callable[[ExtractionResult], ValidationResult]`.
- **The 16 categories:** Parties & Property, Key Dates & Term, Rent & Escalations, CAM & Operating Expenses, Options, Tenant Improvements & Construction, Insurance & Indemnity, Assignment & Subletting, Default & Remedies, Exclusivity & Co-tenancy, Parking & Common Areas, Utilities, Signage & Permitted Use, Miscellaneous, ASC 842 / IFRS 16 Compliance, Casualty / Condemnation / Force Majeure.
